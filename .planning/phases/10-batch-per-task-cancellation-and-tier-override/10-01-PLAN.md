<objective>
Implement the two locked source changes for Phase 10, both confined to the batch fan-out path:
- **BATCH-F01** — thread a real `AbortSignal` into `env.AI.run()` so a timed-out batch task stops
  spending its Workers AI subrequest instead of best-effort racing.
- **BATCH-F03** — tier-only per-task override (`fast` | `standard`) in the batch input, reusing the
  existing allowlist/KV abstraction. No raw model strings at the MCP boundary.

F01 and F03 are tightly coupled: they share the `runTask` signature change and the single batch
adapter line that wires both. They are implemented together in this one source-edit plan so the
shared edits to `src/index.ts` cannot collide. Tests (Plan 02) and docs (Plan 03) follow.

Task 1 is a **pre-existing-tooling fix** (NOT a Phase-10 behavior change): it makes the bare
`npx tsc --noEmit` type-check gate achievable on a clean baseline by excluding the test directory
from the root tsconfig. The test files only type-check under the Workers vitest pool (which injects
`MCP_SECRET` + Workers request types); under a bare `tsc` they raise 32 pre-existing false-positive
errors. Excluding them makes `tsc --noEmit` a meaningful PRODUCTION-code gate for the source edits in
Tasks 2–4.

Purpose: Resolve the two deferred v2.0 batch requirements (BATCH-F01, BATCH-F03) without touching
single-task tool behavior.
Output: Modified `tsconfig.json`, `src/index.ts`, and `src/batch.ts`; full production type-check clean.
