<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Auth form input -> log entry | User-submitted data (PIN, CSRF) must never appear in log output |
| Client IP -> log entry | IP is logged for auth events — acceptable for security audit trail |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05 | Information Disclosure | logAuthEvent in auth handler | mitigate | Log event type and IP only — never log the submitted secret value, CSRF token, or form body content. detail field uses fixed enum strings ("wrong_pin", "csrf_expired"), not user input. |
| T-04-06 | Information Disclosure | Auth GET error logging | mitigate | Replace console.error that logged err.message with logAuthEvent using fixed detail string "auth_init_failed" — prevents leaking parseAuthRequest internals |
| T-04-07 | Repudiation | Auth event audit trail | mitigate | Every auth path (attempt, success, failure, rate_limit) now produces a structured log entry with IP and timestamp — provides audit trail for Cloudflare dashboard |
</threat_model>
