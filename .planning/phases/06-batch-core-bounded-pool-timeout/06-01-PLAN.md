## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Denial of Service | `executeBatch` / `mapWithConcurrency` (unbounded concurrency → subrequest/429 exhaustion) | mitigate | Bounded worker-cursor pool caps peak in-flight at `cfg.concurrency` (default 6); explicitly never `Promise.all` over the task array. Verified by the BATCH-03 in-flight-counter test. |
| T-06-02 | Denial of Service | `executeBatch` over-cap (oversized batch consumes the whole subrequest budget) | mitigate | Pre-dispatch cap check is the first operation in `executeBatch`; `tasks.length > cfg.maxTasks` throws before any worker spawns or any `runTask` runs. Verified by the BATCH-04 zero-dispatch spy. |
| T-06-03 | Denial of Service | `withTimeout` (never-resolving task holds a worker slot forever / event-loop leak via orphaned promise) | mitigate | `withTimeout` guarantees the slot is released at `cfg.taskTimeoutMs`; the two-handler settle-once `.then(onResolve, onReject)` form means a late-settling orphaned promise hits an already-settled promise → no double-settle, no unhandled rejection. Verified by the BATCH-05 late-settle test. |
| T-06-04 | Information disclosure | per-task catch in `executeBatch` (error object leaking stack trace) | mitigate | Error entries carry `err instanceof Error ? err.message : String(err)` — message only, never the stack (consistent with v1.0 logger discipline). |
| T-06-SC | Tampering | npm/pip/cargo installs (supply chain) | accept | No new packages this phase — zero-new-deps constraint; the ~25-line inline pool replaces any third-party concurrency lib (`p-limit` is deliberately not added).
