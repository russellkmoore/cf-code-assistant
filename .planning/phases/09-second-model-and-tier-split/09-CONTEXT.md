<decisions>
## Implementation Decisions

### Model choice (LOCKED, with a gated fallback)
- Run `npm run types` (`wrangler types`) FIRST and check whether `@cf/moonshotai/kimi-k2.7-code` is a key of `AiModels` in `worker-configuration.d.ts`.
  - **Present** → use `@cf/moonshotai/kimi-k2.7-code` (coding-optimized variant — preferred).
  - **Absent** → fall back to `@cf/moonshotai/kimi-k2.5` (already a key in the current generated types — verified). Record which id was used in the commit message.
- Rationale: `ALLOWED_MODELS` is `... as const satisfies ReadonlyArray<keyof AiModels>` (src/index.ts:13). The model id MUST be a valid `keyof AiModels` or the type-check fails — that constraint is the compile-time proof the model is real, which is why the types gate runs first.

### Tier → model mapping (LOCKED — 2-tier, decided via AskUserQuestion)
- `fast` stays `@cf/qwen/qwen3-30b-a3b-fp8`.
- `standard` → chosen Kimi id.
- ALL standard-tier kinds move to Kimi (generateCode, fixBug, reviewCode, transformCode, scaffoldTests, generateDocs, generateTypes, generateWorkerBoilerplate, explainCode-detailed). A third "premium" tier was explicitly REJECTED to keep tier names and tests stable.

### Behavior-preservation invariant (LOCKED)
- Tier **names** (`"fast"` / `"standard"`) and every `TASK_SPECS[kind].resolve(input)` output are UNCHANGED. Only the model that `standard` resolves to changes.
- `resolveModel` (src/index.ts:38), the KV override keys (`config:model:fast` / `config:model:standard`), and the self-healing (delete-invalid-and-fall-back) all keep working unchanged.

### Accepted trade-off (flagged regression risk)
- Pointing `standard` at Kimi moves every standard-tier kind to a ~12× pricier, higher-latency model. Accepted by the user: absolute cost is pennies, and these are the kinds that benefit from a stronger coder. No behavior-shape change (same prompts, same response parsing).
</decisions>
