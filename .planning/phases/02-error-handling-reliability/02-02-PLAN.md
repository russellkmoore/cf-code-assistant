Per Pitfall 4 in RESEARCH.md, wrapping too broadly causes POST handler bugs to return HTML instead of plain-text 400/403.

Replace the current GET block:
```typescript
if (request.method === "GET") {
  const authRequest = await oauthHelpers.parseAuthRequest(request);
  const csrfToken = crypto.randomUUID();
  await env.OAUTH_KV.put(`csrf:${csrfToken}`, JSON.stringify(authRequest), { expirationTtl: 300 });

    headers: { "Content-Type": "text/html" },
  });

```

With:
```typescript
if (request.method === "GET") {
  try {
    const authRequest = await oauthHelpers.parseAuthRequest(request);
    const csrfToken = crypto.randomUUID();
    await env.OAUTH_KV.put(`csrf:${csrfToken}`, JSON.stringify(authRequest), { expirationTtl: 300 });

    return new Response(loginPage(csrfToken), {
      headers: { "Content-Type": "text/html" },
    });
  } catch (err) {
    console.error("[authHandler GET] Failed to initialize auth:", err instanceof Error ? err.message : "unknown");
    return new Response(
      errorPage("Authorization Error", "Failed to initialize the authorization flow. Please try again."),
      {
        status: 500,
        headers: { "Content-Type": "text/html" },
      },
    );
  }
}
```

Key points:
- The `console.error` retains `err.message` for server-side debugging only — it is NOT in the HTML response
- The `errorPage()` call uses hardcoded strings — no user input, no injection risk
- The status is 500 because this represents an unexpected server failure (parseAuthRequest, KV.put, or CSRF generation)
- The try-catch is INSIDE the `if (request.method === "GET")` block, not around the entire /authorize handler
