  <action>
In the auth handler POST block inside `src/index.ts`, add explicit type and emptiness validation for form fields immediately after `request.formData()` and before any KV or secret comparison logic.

Replace the current unsafe casts:
```typescript
const secret = formData.get("secret") as string;
const csrfToken = formData.get("csrf") as string;
```

With validated extraction:
```typescript
const secret = formData.get("secret");
const csrfToken = formData.get("csrf");

if (typeof secret !== "string" || !secret.trim() || typeof csrfToken !== "string" || !csrfToken.trim()) {
  return new Response("Invalid form data.", { status: 400 });
}
```

This ensures:
- Missing fields (null from formData.get) return 400
- Empty or whitespace-only fields return 400
- File uploads (which return File, not string) return 400
- The `as string` unsafe casts are eliminated

The rest of the handler continues to use `secret` and `csrfToken` as strings — TypeScript's control flow analysis narrows them to `string` after the guard.

Also add a size cap to prevent extremely large form submissions from being processed:
```typescript
if (secret.length > 256 || csrfToken.length > 256) {
  return new Response("Invalid form data.", { status: 400 });
}
```

Place this size check immediately after the type/emptiness check, before the KV lookup.
