## Summary

This phase makes `src/index.ts` reject bad inputs before they reach Workers AI, rate-limit PIN brute force, produce type-safe model routing, and never expose internal state in error responses.

The codebase already uses Zod for MCP tool input schemas, so SEC-02 and HARD-03 are additive changes — adding `.max(N)` constraints to existing `z.string()` calls. SEC-01 is a targeted type fix: the `callModel` function passes `model as any` to `env.AI.run()`; replacing this with a proper `keyof AiModels` narrowing eliminates the cast cleanly. SEC-03 is a pre-flight check in `resolveModel()` using an allowlist typed against `keyof AiModels`. HARD-02 is the largest structural change — it requires a new `RateLimit` binding in `wrangler.toml` and a guard at the top of the POST handler.

The native Workers `RateLimit` binding (GA as of September 2025) is the correct solution for HARD-02: counters are cached per Cloudflare location, no KV write overhead per request, and configuration requires only a `[[ratelimits]]` stanza in `wrangler.toml`. Using KV for rate limiting is an inferior alternative — KV write propagation takes up to 60 seconds per the official docs, making it unreliable for real-time enforcement.

**Primary recommendation:** All six requirements are pure `src/index.ts` edits plus a `wrangler.toml` binding addition. No new npm dependencies needed.

### Pattern 1: Type-Safe Model Routing (SEC-01)

**What:** Replace `model as any` in `callModel` with a type that satisfies `keyof AiModels`.

**Current code (line 103 of src/index.ts):**
```typescript
const response = await env.AI.run(model as any, { ... });
```

**Fix:** Narrow the `model` parameter type in `callModel` to `keyof AiModels`:
```typescript
// Source: worker-configuration.d.ts — Ai.run signature
// run<Name extends keyof AiModelList, ...>(model: Name, ...)
async function callModel(
  env: Env,
  model: keyof AiModels,  // was: string
  userPrompt: string,
  maxTokens: number
): Promise<string> {
  const response = await env.AI.run(model, { ... }); // no cast needed
  ...
}
```

**Note:** `resolveModel()` returns `string` from KV. After adding the allowlist check (SEC-03), the validated model is narrowed to `keyof AiModels` before being passed to `callModel`. The `DEFAULT_MODELS` values are already valid string literals — change their type to `Record<ModelTier, keyof AiModels>` to make the defaults provably valid.

**Why this works:** The `Ai.run` signature is:
```typescript
run<Name extends keyof AiModelList>(model: Name, inputs: ...) // from worker-configuration.d.ts line 9542
```
`@cf/qwen/qwen3-30b-a3b-fp8` appears at line 9444 of `worker-configuration.d.ts` as a key of `AiModels`, so it satisfies the constraint with no cast. [VERIFIED: worker-configuration.d.ts, generated 2026-04-12]

### Pattern 2: Model Allowlist Validation (SEC-03)

**What:** Validate KV-sourced model names against an explicit allowlist before passing to `callModel`.

```typescript
// Typed against keyof AiModels so allowlist entries are compiler-checked
const ALLOWED_MODELS = [
  "@cf/qwen/qwen3-30b-a3b-fp8",
] as const satisfies ReadonlyArray<keyof AiModels>;

type AllowedModel = typeof ALLOWED_MODELS[number]; // = "@cf/qwen/qwen3-30b-a3b-fp8"

function isAllowedModel(model: string): model is AllowedModel {
  return (ALLOWED_MODELS as readonly string[]).includes(model);
}

async function resolveModel(env: Env, tier: ModelTier): Promise<keyof AiModels> {
  const kvKey = `config:model:${tier}`;
  const override = await env.OAUTH_KV.get(kvKey);
  if (override !== null && isAllowedModel(override)) {
    return override; // validated
  }
  if (override !== null) {
    // Invalid model in KV — delete it (self-healing preserved)
    await env.OAUTH_KV.delete(kvKey);
  }
  return DEFAULT_MODELS[tier];
}
```

**Key design:** The self-healing behavior (delete bad KV, return default) is preserved and simplified — no longer needs the error-catch path in `runAI` for "Unknown model" errors, because bad values are rejected before reaching `ai.run()`.

### Pattern 4: Rate Limiting Auth (HARD-02)

**What:** Reject more than 5 PIN attempts from the same IP within 60 seconds.

**wrangler.toml addition:**
```toml
[[ratelimits]]
name = "AUTH_RATE_LIMITER"
namespace_id = "1"

[ratelimits.simple]
limit = 5
period = 60
```

**Env interface addition:**
```typescript
interface Env {
  AI: Ai;
  OAUTH_KV: KVNamespace;
  MCP_SECRET: string;
  AUTH_RATE_LIMITER: RateLimit;  // add this
}
```

**Auth handler POST guard (before form parsing):**
```typescript
if (request.method === "POST") {
  const ip = request.headers.get("CF-Connecting-IP") ?? "unknown";
  const { success } = await env.AUTH_RATE_LIMITER.limit({ key: ip });
  if (!success) {
    return new Response("Too many attempts. Try again later.", { status: 429 });
  }
  // ... rest of form processing
}
```

**Note:** `CF-Connecting-IP` is the canonical IP header injected by Cloudflare's edge — it is always present in production Worker requests. [CITED: developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/]

**Note on period:** The `RateLimit` binding only supports `period` of 10 or 60 seconds. [VERIFIED: Cloudflare docs 2026-04-12] The requirement of "5 per minute" maps exactly to `limit=5, period=60`.

### Pattern 5: Error Sanitization (SEC-04)

**What:** Wrap all tool handlers and auth code so that exceptions never propagate raw error details to clients.

**Current situation:** Tool handlers call `runAI` which can throw. If the MCP SDK doesn't catch, an uncaught exception could propagate a raw Error message or stack trace in a 500 response.

**Pattern — tool handler wrapper:**
```typescript
// In each tool handler, catch and return a safe message
async ({ code }) => {
  try {
    const result = await runAI(env, "standard", prompt, 4096);
    return { content: [{ type: "text", text: result }] };
  } catch {
    return {
      content: [{ type: "text", text: "The code generation service encountered an error. Please try again." }],
    };
  }
}
```

**Auth handler — never include raw KV data or error details in responses:**
```typescript
// BAD (current):
return new Response("Session expired. Please try again.", { status: 400 }); // this is fine
// But if JSON.parse(stored) throws, let it bubble? — should catch

// GOOD:
try {
  const authRequest = JSON.parse(stored) as AuthRequest;
  ...
} catch {
  return new Response("Authorization failed.", { status: 400 });
}
```

**Key rules:**
1. Never include `err.message` or `err.stack` in Response bodies
2. Never include KV values in Response bodies
3. Return generic status messages: "Bad request", "Unauthorized", "Service error"
4. Phase 4 will add structured internal logging — for now, `console.error` is acceptable for server-side context

### Anti-Patterns to Avoid

- **Returning raw error messages to clients:** `new Response(err.message, { status: 500 })` leaks internal state
- **Using KV as a rate limiter:** Write propagation delay makes KV counters unreliable for brute force; use native `RateLimit` binding
- **`model as any` or `model as keyof AiModels`:** The latter is a cast that skips validation; use a type guard / allowlist instead
- **Blocking the rate limiter check on the response parsing:** Rate limit check must be the first thing in the POST handler, before any async work

## Common Pitfalls

### Pitfall 1: Rate Limit Period Must Be 10 or 60
**What goes wrong:** Setting `period = 120` or any value other than 10 or 60 causes a deployment error.
**Why it happens:** The `RateLimit` binding only supports two window sizes by design.
**How to avoid:** Use `period = 60` (maps exactly to "5 per minute" requirement).
**Warning signs:** `wrangler deploy` error mentioning invalid rate limit config.

### Pitfall 2: `callModel` Still Accepts `string` After the Fix
**What goes wrong:** If `callModel`'s parameter type is widened back to `string` (e.g., through a refactor), the `as any` problem silently returns.
**Why it happens:** TypeScript doesn't prevent widening from a narrower call site.
**How to avoid:** Type `callModel`'s `model` parameter as `keyof AiModels` — this is enforced at compile time.
**Warning signs:** `npx tsc --noEmit` passes when it should fail if a non-allowlist model is passed.

### Pitfall 3: `satisfies` Requires the Allowlist Entries to Be Literal Types
**What goes wrong:** If `ALLOWED_MODELS` is typed as `string[]`, the `satisfies ReadonlyArray<keyof AiModels>` check won't catch typos.
**Why it happens:** `string` satisfies `keyof AiModels` at the type level even though it's not a valid model.
**How to avoid:** Use `as const satisfies ReadonlyArray<keyof AiModels>` — the `as const` makes entries literal, the `satisfies` checks them.
**Warning signs:** A misspelled model name in `ALLOWED_MODELS` doesn't produce a TypeScript error.

### Pitfall 4: `CF-Connecting-IP` Is Undefined in Local Dev
**What goes wrong:** `request.headers.get("CF-Connecting-IP")` returns `null` when running `wrangler dev` locally, causing the rate limiter key to be `"unknown"` for all requests — all local requests share one rate limit slot.
**Why it happens:** The header is injected by the Cloudflare edge, not by the local dev server.
**How to avoid:** The `?? "unknown"` fallback is correct — this is acceptable for local dev. In production, the header is always present. Document this behavior.
**Warning signs:** All local dev login attempts fail after 5 total attempts.

### Pitfall 5: `RateLimit` Binding Not Available in Local Dev Without Proper Config
**What goes wrong:** `wrangler dev` fails if `namespace_id` is malformed or missing.
**Why it happens:** The `namespace_id` must be a string representation of a positive integer.
**How to avoid:** Use a simple integer like `"1"` — the value is scoped to the account, so `"1"` is fine for a single-purpose binding.

### Pitfall 6: JSON.parse of KV-stored AuthRequest Can Throw
**What goes wrong:** If the CSRF KV value is corrupted or not valid JSON, `JSON.parse(stored)` throws, and the current code has no catch for this path in the auth POST handler.
**Why it happens:** No guard on `stored` before parsing.
**How to avoid:** Wrap `JSON.parse` in a try/catch (also covered by SEC-04 requirement).

### Pitfall 7: Zod v4 Breaking Changes
**What goes wrong:** The project uses `zod@^4.0.0`. Zod v4 has significant API changes from v3.
**Why it happens:** Some community examples use Zod v3 patterns.
**How to avoid:** `.max(N)` and `.trim()` work identically in both Zod v3 and v4 — no issue for this phase. [VERIFIED: zod.dev/api 2026-04-12]

## Code Examples

### SEC-01 and SEC-03 Together — resolveModel + callModel

```typescript
// Source: worker-configuration.d.ts (generated by wrangler types)
// AiModels interface contains all model names as keys; Ai.run expects keyof AiModels

const ALLOWED_MODELS = [
  "@cf/qwen/qwen3-30b-a3b-fp8",
] as const satisfies ReadonlyArray<keyof AiModels>;

const DEFAULT_MODELS: Record<ModelTier, keyof AiModels> = {
  fast: "@cf/qwen/qwen3-30b-a3b-fp8",
  standard: "@cf/qwen/qwen3-30b-a3b-fp8",
};

function isAllowedModel(model: string): model is typeof ALLOWED_MODELS[number] {
  return (ALLOWED_MODELS as readonly string[]).includes(model);
}

async function resolveModel(env: Env, tier: ModelTier): Promise<keyof AiModels> {
  const kvKey = `config:model:${tier}`;
  const override = await env.OAUTH_KV.get(kvKey);
  if (override !== null) {
    if (isAllowedModel(override)) return override;
    await env.OAUTH_KV.delete(kvKey); // self-heal: delete invalid KV entry
  }
  return DEFAULT_MODELS[tier];
}

async function callModel(
  env: Env,
  model: keyof AiModels,  // narrowed — no cast needed
  userPrompt: string,
  maxTokens: number,
): Promise<string> {
  const response = await env.AI.run(model, {
    messages: [
      { role: "system", content: SYSTEM_PROMPT },
      { role: "user", content: userPrompt },
    ],
    max_tokens: maxTokens,
  });
  const result = response as { response?: string };
  return result.response ?? JSON.stringify(response);
}

// runAI simplifies — no longer needs the "Unknown model" catch path
async function runAI(env: Env, tier: ModelTier, userPrompt: string, maxTokens = 4096): Promise<string> {
  const model = await resolveModel(env, tier); // always returns keyof AiModels
  return callModel(env, model, userPrompt, maxTokens);
}
```

## Open Questions (RESOLVED)

1. **Should `ALLOWED_MODELS` be the single source of truth for both tiers, or should each tier have its own allowlist?**
   - What we know: Both tiers currently default to the same model. The allowlist is per-model, not per-tier.
   - What's unclear: If a future model is fast-only or standard-only, a shared allowlist doesn't express that.
   - RESOLVED: Single flat allowlist used (see Plan 01-02 `ALLOWED_MODELS`). Tier-specific allowlists deferred as future refinement.

2. **Should tool handler `try/catch` return an MCP error object or a text message?**
   - What we know: Current handlers return `{ content: [{ type: "text", text }] }`. MCP SDK also supports error content type.
   - What's unclear: Whether Claude (as MCP client) handles error content differently from text content.
   - RESOLVED: Return text content with human-readable message (see Plan 01-04 Task 2). MCP error type deferred to Phase 2 structured error responses.
