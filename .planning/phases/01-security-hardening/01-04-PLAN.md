**1. Add rate limit binding to wrangler.toml:**

Append this stanza at the end of `wrangler.toml`:

```toml
[[ratelimits]]
binding = "AUTH_RATE_LIMITER"
namespace_id = "1"

[ratelimits.simple]
limit = 5
period = 60
```

IMPORTANT: The `period` value MUST be either 10 or 60 — no other values are supported by the Workers RateLimit binding. Use 60 to match the "5 per minute" requirement.

**2. Add AUTH_RATE_LIMITER to the MANUAL Env interface in src/index.ts:**

The authoritative `Env` interface is the one declared in `src/index.ts` (currently at line 93), NOT the generated one in `worker-configuration.d.ts`. The generated file produces a global `interface Env extends Cloudflare.Env {}` but `src/index.ts` is a module (has top-level imports), so its local `Env` declaration shadows the global. Add the new binding to the local one:

```typescript
interface Env {
  AI: Ai;
  OAUTH_KV: KVNamespace;
  MCP_SECRET: string;
  AUTH_RATE_LIMITER: RateLimit;
}
```

This updates the generated types to include the new ratelimits binding in `Cloudflare.Env`. Even though the manual `Env` in `src/index.ts` is authoritative, keeping the generated types in sync avoids confusion.

**1. Wrap every AI-calling tool handler with try/catch that returns a generic error:**

There are 11 tool handlers that call `runAI` (all except `routingInfo`). Each handler's async function body must be wrapped in a try/catch. The catch block returns a generic MCP text response — never `err.message`, never `err.stack`, never any internal details.

For each of the 11 tools, wrap the handler like this:

```typescript
async ({ param1, param2 }) => {
  try {
    // ... existing prompt assembly and runAI call ...
    return { content: [{ type: "text", text: result }] };
  } catch {
    return {
      content: [{ type: "text", text: "An error occurred while processing your request. Please try again." }],
    };
  }
}
```

The tools to wrap (verify all 11):
1. generateCode
2. reviewCode
3. transformCode
4. scaffoldTests
5. quickTask
6. explainCode
7. generateDocs
8. generateTypes
9. fixBug
10. generateCommitMessage
11. generateWorkerBoilerplate

`routingInfo` does NOT need wrapping — it returns a static string, no AI call.

Use `catch {` (no error variable binding) to prevent accidental use of `err.message`. This is intentional — in this phase, errors go to `console.error` only (Phase 4 adds structured logging). If the executor wants to add `console.error` for server-side visibility, that is acceptable:

```typescript
catch (err) {
  console.error("Tool error:", err instanceof Error ? err.message : "unknown");
  return {
    content: [{ type: "text", text: "An error occurred while processing your request. Please try again." }],
  };
}
```

Either form (with or without console.error) is acceptable. The critical rule: the Response/MCP content must NEVER include `err.message`, `err.stack`, or any dynamic error detail.

**2. Wrap the auth handler's JSON.parse with try/catch:**

In the auth handler POST block, the `JSON.parse(stored)` call (which parses the CSRF-stored auth request) currently has no error handling. Wrap it:

```typescript
let authRequest: AuthRequest;
try {
  authRequest = JSON.parse(stored) as AuthRequest;
} catch {
  return new Response("Authorization failed.", { status: 400 });
}
```

This prevents a corrupted KV value from causing an unhandled exception that could leak parse error details.

**3. Wrap the `oauthHelpers.completeAuthorization` call:**

The `completeAuthorization` call can also throw. Wrap it:

```typescript
let redirectTo: string;
try {
  const result = await oauthHelpers.completeAuthorization({
    request: authRequest,
    userId: "owner",
    metadata: { label: "claude-code" },
    scope: authRequest.scope,
    props: { userId: "owner" },
  });
  redirectTo = result.redirectTo;
} catch {
  return new Response("Authorization failed.", { status: 400 });
}

return Response.redirect(redirectTo, 302);
```

**Key rules for error sanitization (SEC-04):**
- NEVER include `err.message` in any Response body or MCP content text
- NEVER include `err.stack` in any Response body or MCP content text
- NEVER include KV values in Response bodies
- Use generic messages: "An error occurred...", "Authorization failed.", "Bad request."
- `console.error` for server-side context is acceptable (Cloudflare captures via wrangler tail)
